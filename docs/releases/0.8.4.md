Bosun 0.8.4 drops the word "native" from the firmware and makes Captain
updates through a Raspberry Pi more reliable. Update the Raspberry Pi first,
then the app and the Captain firmware.

## Changes

- **The firmware is just "Bosun" now.** It reports its plain release (`0.8.4`
  instead of `0.8.3-native`), the USB device is named "MIDI Captain Bosun",
  and the firmware download is `Bosun-0.8.4-firmware-update.zip`. "Native" only
  told this firmware apart from the CircuitPython one, which Bosun no longer
  ships. The app also shows a Captain that still runs an older release without
  the suffix. Profiles, bindings and settings are not affected. Windows can
  keep showing the old USB name until the pedal is unplugged and plugged in
  again.
- **Updating the Captain through a Raspberry Pi no longer stops with
  "picotool failed: No accessible RP-series device in BOOTSEL mode".** The Pi
  opened the Captain a few milliseconds after it entered its bootloader, before
  the device was ready, and gave up at once. It now keeps trying for a few
  seconds. When it stopped, nothing had been written and the Captain returned
  to its previous firmware.

A Raspberry Pi that still runs 0.8.2 or 0.8.3 accepts the 0.8.4 firmware
package, but update the Pi first to get the fix above.

## Downloads

| System | Package | Installation |
| --- | --- | --- |
| Windows x64 | `Bosun-<version>-portable-x64.zip` | Extract the whole ZIP and run `Bosun.exe`. Requires WebView2. |
| macOS, Apple Silicon (untested) | `.dmg` | Open it and copy Bosun to Applications. |
| Linux x64 (untested) | `.AppImage` | Make it executable, then open it. |
| Android 10 or later | `bosun.apk` | Install the APK; connect over USB-OTG or through a Pi hub. |

The release also carries the offline setup guide
(`Bosun-0.8.4-setup-guide.html`), the Raspberry Pi setup package
(`Bosun-0.8.4-pi-setup.tar.gz`), the firmware update package
(`Bosun-0.8.4-firmware-update.zip`), the browser Stage (`Bosun-0.8.4-stage.zip`)
and `SHA256SUMS.txt`.

## Testing

Both changes come with regression tests in the firmware, Desktop and Raspberry
Pi test suites. The update stop was reproduced and diagnosed on a 10-switch
Captain behind a Raspberry Pi 3.

Everything else is unchanged from
[0.8.3](https://github.com/danmigdev/bosun-midi-captain/blob/main/docs/releases/0.8.3.md).
