# Bosun 0.6.9

Stage now has a compact **BASE → MORPH** bar with optional position and button
controls. This release also fixes the native Morph Pedal command, which sent
CC4 instead of Kemper's CC11.

## Changes

- Tap the Morph bar to show **Base**, **Morph**, a **0–100% position slider** and
  **Trigger Morph**. The same Stage component serves Desktop, Android and Pi/browser.
- Display **Set 65%** for the last position sent by Bosun, or **?** when unknown.
  Clear stale indications after rig/profile changes, reconnects, detected external
  Morph traffic, failed sends and button triggers. No simulated progress ramp.
- Add **+ Morph Button** to unbound Kemper footswitches, creating paired press/release
  actions. Existing assignments retain their saved format.
- Show Morph position in percent in the editor and clarify the expression-pedal
  assignment. Add an optional Captain Screen field for the last commanded position.
- Guard Stage controls against stale profiles/rig generations and order hub context
  reads after Morph commands.

Kemper does not provide complete Morph state feedback. The bar shows the last
command sent, not confirmed device state. Button timing and momentary behaviour
remain controlled by the Kemper rig. Read the [Morph guide](https://github.com/danmigdev/bosun-midi-captain/blob/v0.6.9/docs/morph.md).

## Installation and validation

Update both Bosun and Captain native firmware to **0.6.9**. Pi setups also need
the matching hub and Stage. This is a normal native update; existing profiles
are preserved. [Update instructions](https://github.com/danmigdev/bosun-midi-captain/blob/v0.6.9/docs/firmware-updates.md).

Frontend, native firmware and hub tests cover the new behaviour, including failure
and stale-state handling. Browser checks cover desktop, HDMI and phone layouts
with a simulated device. **Physical Kemper Morph validation remains pending.**
macOS and Linux runtime operation remains untested.
