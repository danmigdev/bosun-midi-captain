# Bosun 0.6.8

Bosun Desktop now detects the 10-switch MIDI Captain running stock PaintAudio
5.15 and can install native firmware directly from the setup wizard. Published
Desktop 0.6.7 did not recognize that firmware's USB identity.

## Fixes

- Recognize the stock USB identity during first installation, while retaining
  the existing device checks for native firmware updates.
- Request the stock firmware's USB bootloader automatically with its 1200-baud
  reset procedure. Connect the Captain normally, select it and choose **Install**.
- Correct the setup instructions: holding footswitch 1 opens PaintAudio USB
  Setup, not the `RPI-RP2` bootloader.
- Update the in-app FAQ, offline guide and documentation with the hardware test
  result and the correct first-installation procedure.

The installer still verifies the physical device, flash identity and 8 MiB
capacity, saves and verifies a full backup before writing, and checks the
complete flash readback. New installations use **0.6.8-native** directly;
no older Bosun firmware, CircuitPython bootstrap or Pi is required.

## Validation

A complete Windows hardware test passed from official PaintAudio **5.15** on
the **10-switch RP2040 Captain with 8 MiB flash**. The test covered automatic
bootloader entry, full backup, native installation, restoration of the original
configuration and all six patches, and reconnection to Kemper Player and Stage.

That hardware trial used the corrected local 0.6.7 build and 0.6.7-native. This
release carries the tested installer corrections and advances the bundled
firmware version; the complete hardware trial was not repeated with the final
0.6.8 binaries. See the [full test report](https://github.com/danmigdev/bosun-midi-captain/blob/v0.6.8/docs/stock-installation-test.md).

**macOS and Linux apps remain untested on real systems.** Other stock firmware
versions, other Captain models, fresh Pi-card installation and interrupted-write
recovery are outside this hardware test's scope.
