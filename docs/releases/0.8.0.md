# Bosun 0.8.0: MIDI Captain Mini 6 support (experimental)

Bosun now runs on the 6-switch **PaintAudio MIDI Captain Mini 6** as well as
the 10-switch MIDI Captain. Mini 6 support follows the community pin map
(PySwitch) and has **not been tested on a real Mini 6** yet. Nothing changes
for 10-switch Captains.

- One native firmware serves both models. The pedal stores its model outside
  every profile; a pedal without a stored model runs as the 10-switch Captain,
  so existing installations behave exactly as before.
- The installer asks which Captain you have, checks for the required 8 MiB of
  flash before writing anything, and stores the model after installing.
- **Maintenance → Pedal model** changes the model later: the pedal restarts
  and keeps its profiles. A freshly installed pedal without a stored model asks
  for it before the first profile is created.
- The editor, Stage, the Raspberry Pi HDMI display and the pedal simulator draw
  the connected pedal's layout: two rows of three switches on the Mini 6.
- The Mini 6 has no expression jacks: expression settings are hidden and the
  firmware never drives those pins.
- Configurations copied from another model keep bindings and settings for
  switches the pedal lacks. They never fire, and the editor lists them for
  removal. Configuration backups record the model they came from.
- Desktop and Raspberry Pi updates check that the pedal reports the same model
  afterwards.
- The boot recovery shortcut (hold switch 1 for three seconds at power-on) now
  ignores switches 4, UP, D and DOWN, so it works the same on both models.

See the [MIDI Captain Mini 6 notes](../mini6.md).

Developers: the native application is now also tested against PySwitch's
virtual Kemper over loopback MIDI, with no Captain or Kemper attached; see
[Kemper integration tests](../kemper-emulator-tests.md). Host builds of the
native firmware now need Node.js 22.

## Before upgrading

Use matching Desktop, native Captain firmware and Pi/Stage assets. Keep the
verified full-flash backup created before upgrading. Upgrading from 0.6.x
expands configuration storage from 512 KiB to 4 MiB on the first configuration
write; once expanded, downgrading requires restoring that backup. See
[firmware update and recovery](../firmware-updates.md).
