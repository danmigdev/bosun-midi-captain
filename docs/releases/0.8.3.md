Bosun 0.8.3 fixes bugs found in 0.8.2 and makes Stage steadier on rig
changes. Update the app, the Captain firmware and the Pi components together.

## Stage

- **Rig changes no longer look like a reload.** The Morph bar used to vanish
  for a moment, so the switch grid jumped; the title showed the bank/slot
  number and every switch label blanked to "-". Now the layout stays put, the
  new rig's name appears at once, and the switch tiles keep their labels,
  unlit and inactive, until the new rig's assignments arrive. Effects still
  light up only when the Kemper reports them. BPM and the tuner no longer
  blink out, and a tuner you closed stays closed.
- **A clearer Morph bar**: a framed readout with larger text and a thicker
  bar. **Unknown** replaces **?** (the Kemper does not report its Morph
  position, so Bosun only knows what it sent), and a **Controls** button
  replaces **+**. The controls stay open across rig changes.
- **Stage appearance** has new **Morph bar** and **Morph controls** sections
  for the size and font of the bar text and of its controls.

## Fixes

- **Restoring a large backup** over the active profile no longer stops
  part-way. A restore first deletes the profile's patches, then wrote each
  backup patch as an unsaved change, and the Captain keeps at most 128
  unsaved changes: a backup with more than 128 patches stopped at the 129th.
  Each restored patch is now saved as it is written, so Discard can no longer
  drop a restore either.
- **Android: accented names** no longer arrive corrupted when a character is
  split across two USB transfers.
- **Android: commands are no longer lost after a slow USB write.** When a write
  ran out of time part-way, the app sent the whole command again and the
  Captain received it garbled. The app now sends only the missing part.
- **Android: device detection** falls back to the USB vendor ID when the
  Kemper or the Captain does not report its name yet.
- **Quick setup** waits for the Captain to confirm each binding, reports a
  failure instead of success, and also writes the patches linked to the open
  one by a locked column.
- **First-run setup** derives the profile ID from the whole profile name
  (typing "Live rig" gave the ID "l") and keeps it within 32 characters.
- **Kemper identity**: when the identity request cannot be sent, the Captain
  reports a MIDI send failure instead of a storage error.

## Downloads

| System | Package | Installation |
| --- | --- | --- |
| Windows x64 | `Bosun-<version>-portable-x64.zip` | Extract the whole ZIP and run `Bosun.exe`. Requires WebView2. |
| macOS, Apple Silicon (untested) | `.dmg` | Open it and copy Bosun to Applications. |
| Linux x64 (untested) | `.AppImage` | Make it executable, then open it. |
| Android 10 or later | `bosun.apk` | Install the APK; connect over USB-OTG or through a Pi hub. |

The release also carries the offline setup guide
(`Bosun-0.8.3-setup-guide.html`), the Raspberry Pi setup package
(`Bosun-0.8.3-pi-setup.tar.gz`), the firmware update package
(`Bosun-0.8.3-native-update.zip`), the browser Stage (`Bosun-0.8.3-stage.zip`)
and `SHA256SUMS.txt`.

## Testing

Every fix comes with a regression test in the firmware, Desktop or Android
test suites. The Android fixes have not been tried on a phone yet. The Stage
rig change was recorded frame by frame on a 10-switch Captain and a Kemper
Player at the Pi panel's 1920 x 440.

Supported hardware, setup and known limitations are unchanged from
[0.8.2](https://github.com/danmigdev/bosun-midi-captain/blob/main/docs/releases/0.8.2.md).
