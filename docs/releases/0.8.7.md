Bosun 0.8.7 fixes the Stage display of a Raspberry Pi: it no longer stays on a
white browser page, and it comes back by itself if its page ever stops.

## Changes

- **Stage no longer stays on a white page.** On a Raspberry Pi 3, Stage could
  end on the browser's "Aw, Snap!" page, typically when the Captain was
  switched on after the Pi, and only replugging HDMI brought it back.
  - The cause is Chromium 156.0.8078.73 from Raspberry Pi, which can crash at
    random on the Pi 3's processor (Cortex-A53 erratum 843419). Raspberry Pi's
    156.0.8078.108 does not.
  - Installing or updating Bosun on a Pi with that processor (Pi 3, Zero 2 W)
    now updates an older Chromium when the Pi is online. Other Pis and newer
    Chromium versions stay as they are. Offline, Bosun installs all the same
    and says that Chromium was not updated.
- **Stage restarts by itself.** If the Stage page crashes or hangs, the Pi
  restarts the display in under a minute, or within a few minutes if Stage
  does not appear at all after a start. The hub, MIDI and the Captain keep
  running.
- **Replugging HDMI no longer restarts Stage.** The display program used to
  crash each time a panel was reconnected.
- **More reliable start.** The browser waits for the hub and for a stable HDMI
  output. It could crash while the panel was being set up, and on a Pi without
  a network it could stay on "This site can't be reached".
- While there is nothing to show, the display is dark instead of white.

Update the Raspberry Pi first, then the app and the Captain firmware. Bosun
Desktop does both with Maintenance > "Update Bosun". On a Pi 3 with an older
Chromium the Pi update takes several minutes more: keep the Pi powered and
online. The Captain firmware changes only its version number.

If the display stays on an error page with an older Bosun, replug HDMI or run
`sudo systemctl restart bosun-kiosk.service` on the Pi.

## Downloads

| System | Package | Installation |
| --- | --- | --- |
| Windows x64 | `Bosun-<version>-portable-x64.zip` | Extract the whole ZIP and run `Bosun.exe`. Requires WebView2. |
| macOS, Apple Silicon (untested) | `.dmg` | Open it and copy Bosun to Applications. |
| Linux x64 (untested) | `.AppImage` | Make it executable, then open it. |
| Android 10 or later | `bosun.apk` | Install the APK; connect over USB-OTG or through a Pi hub. |

The release also carries the offline setup guide
(`Bosun-0.8.7-setup-guide.html`), the Raspberry Pi setup package
(`Bosun-0.8.7-pi-setup.tar.gz`) with its signature
(`Bosun-0.8.7-pi-setup.tar.gz.sig`), the firmware update package
(`Bosun-0.8.7-firmware-update.zip`), the browser Stage (`Bosun-0.8.7-stage.zip`)
and `SHA256SUMS.txt`.

## Testing

Tested on a Raspberry Pi 3 with a 10-switch Captain and a Kemper Player. The
crash was reproduced there: with the old Chromium, 3 of 8 starts with a
simulated Captain switched on later lost the Stage page; with the update, 0 of
21. Simulated HDMI replugs, a page stopped on purpose, the Captain's USB
connection switched off and on, and three restarts of the Pi were also tested.
Switching the Captain on with its own power switch, and the installer updating
an old Chromium on a Pi, have not been tested.

Everything else is unchanged from
[0.8.6](https://github.com/danmigdev/bosun-midi-captain/blob/main/docs/releases/0.8.6.md).
