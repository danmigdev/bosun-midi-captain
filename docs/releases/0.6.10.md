# Bosun 0.6.10

Fixes Delay appearing OFF on Captain and Stage when it is enabled immediately
after changing rigs, such as **CLEAN -> CRUNCH -> DELAY**. The Kemper activated
Delay correctly, but Bosun's subsequent state query could overwrite the display
with an incorrect OFF value.

## Changes

- Query Delay and Reverb through their current effect-module parameters. The
  Player's older notification addresses can return an incorrect value when queried.
- Continue receiving the older addresses the Player uses for live notifications.
- Protect live Delay/Reverb changes from replies to earlier state requests.
- Use the corrected queries for rig reconciliation, explicit state refresh and
  expression-mode discovery.

This is a native Captain firmware fix. Existing patch assignments and saved
configuration are preserved. Update Captain using the matching native package
in Bosun Desktop **0.6.10**; existing Stage clients receive the corrected state.
See the [firmware update guide](https://github.com/danmigdev/bosun-midi-captain/blob/v0.6.10/docs/firmware-updates.md).

## Validation

Native regression tests cover the captured failure, rapid rig changes, Delay
and Reverb notifications, delayed replies and the debounced switch state sent
to Stage. The native host tests and RP2040 firmware build passed.

Hardware validation on the connected Captain and Kemper Player passed **12
Delay and 3 Reverb transition cases**, including all nine timings that reproduced the bug.
Independent current-parameter reads and the Captain LED framebuffer confirmed
the effect stayed ON and the next press turned it OFF. The production Pi Stage
page agreed in all 15 cases in a browser. Test actions used network switch activation;
physical GPIO/debounce behaviour is covered separately by native tests.
The Pi updater verified a full recovery backup and preserved the configuration.

macOS and Linux runtime operation remains untested. Physical Kemper Morph
validation remains pending; this fix concerns effect on/off feedback.
